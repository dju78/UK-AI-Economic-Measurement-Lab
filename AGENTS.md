# AGENTS.md — Mandatory Context for AI Coding Agents

Project: **UK AI Economic Measurement Lab**  
Owner: **Daramola Omoyele**  
Version: **0.1.0-planning**


> **Status and independence.** This project is an independent research and software prototype. It is not an Office for National Statistics (ONS) product, is not endorsed by ONS, and must not present experimental outputs as official statistics. Published ONS values must be labelled as ONS source data; prototype decompositions must be labelled as illustrative/experimental estimates with assumptions and uncertainty shown.


## Prime directive

Build a **credible statistical research product**, not a decorative dashboard. Every number must have provenance; every modelled number must expose its method, assumptions and uncertainty; every page must distinguish source data from experimental estimates.

## Non-negotiable rules

1. **Never invent data.** If a required source is unavailable, build a clearly marked placeholder state and add a data-gap issue.
2. **Never relabel a broad CPA total as AI output.** ONS explicitly states the broad categories contain both AI and non-AI activity. [S1]
3. **Never claim an experimental decomposition is official.** Use labels such as `Illustrative experimental estimate`, `Scenario`, or `Prototype output`.
4. **Never imply ONS endorsement or employment.** The site is independent.
5. **Preserve source values.** Raw input data are immutable; transformations are versioned.
6. **Reproducibility first.** Every analytical result must be reproducible from a documented pipeline.
7. **Accessibility first.** Keyboard navigation, semantic headings, chart alternatives, colour-independent encoding and readable tables are required. [S11]
8. **Method transparency.** Every estimate must link to a method card containing formula, data source, period, assumptions, limitations and version.
9. **Human review for AI classification.** Model/LLM output may propose labels but must not silently become ground truth.
10. **Quality gate before public release.** Unit tests, data-validation tests, calculation tests, accessibility checks and a signed validation report are mandatory.

## Statistical anchor

ONS is developing a thematic account aligned with National Accounts principles. The published roadmap includes scoping and data-landscape work through Q1 2027, prototype decomposition work during Q2–Q4 2027 and an experimental account targeted for readiness to productionise in Q1 2028. [S1]

The product should complement this public research problem. It should **not** pretend to reproduce ONS internal methods or unpublished data.

## Core concepts the code must understand

- thematic account
- supply and use tables
- CPA product groups
- SIC industrial classification
- domestic output and imports
- intermediate demand and final demand
- GVA and GDP
- GFCF / asset boundary
- production boundary
- economic ownership and UK residency
- licence/cloud access versus creation of an owned non-financial asset
- AI producer versus AI adopter
- dedicated versus diversified AI activity

## Required source labels in the UI

Use three visual statuses:

- **Published official-statistics source** — direct published ONS/other official source.
- **Published research/context source** — official research or methodology not itself an official statistical estimate.
- **Prototype estimate** — generated by this project; must show method and uncertainty.

## Architecture preference

Frontend: Next.js + React + TypeScript.  
Analytical services: Python.  
Local analytical store: DuckDB + Parquet.  
Validation: Pandera or equivalent + pytest.  
Charts: accessible React charting library or custom SVG with data-table alternative.  
CI: GitHub Actions.  
Deployment: Vercel (frontend) plus suitable Python service, or a single container platform if simpler.

The architecture may change only through a documented Architecture Decision Record.

## Before changing methodology

Read `02_STATISTICAL_MEASUREMENT_FRAMEWORK.md`, `06_DISAGGREGATION_METHODOLOGY_SPEC.md`, and `16_RISK_ASSUMPTIONS_DECISIONS.md`. Record material changes in the decision log template.

## Definition of success

A reviewer should be able to answer, without asking the developer:

- Where did this number come from?
- Is it published data or modelled?
- Which population and period does it describe?
- Which formula/model produced it?
- What assumptions were made?
- How sensitive is the result to those assumptions?
- What would make the estimate wrong?
- Can I reproduce it?
